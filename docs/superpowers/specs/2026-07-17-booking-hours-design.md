# 공개 예약 가능 시간 변경 설계

## 목표

- 모든 공개 예약 화면의 예약 가능 시간을 `07:00~23:00`으로 통일한다.
- `23:00`에 끝나는 예약은 허용하고 `23:00` 이후까지 이어지는 예약은 막는다.
- 화면 선택 제한과 서버 검증에 같은 정책을 적용한다.

## 예약 시간 정책

공통 예약 정책은 시작 경계 `07:00`, 종료 경계 `23:00`을 사용한다.

- 가장 이른 시작: `07:00`
- 가장 늦은 종료: `23:00`
- `22:30~23:00` 30분 예약: 가능
- `22:00~23:00` 1시간 예약: 가능
- `22:30~23:30` 1시간 예약: 불가
- `07:00` 이전 시작 또는 `23:00` 이후 종료: 불가

`src/lib/reservations.ts`에 공개 예약 시작·종료 시각과 운영시간 오류 문구를 공통 정책으로 둔다. 하루 전체를 표현하는 `00:00~24:00` 상수는 관리자 시간표, 점검 등록, 기존 일정 표시를 위해 유지한다.

## 화면과 서버

기본 예약·예약 변경 화면은 공통 예약 정책 안에서 가능한 30분·1시간 선택지만 만든다. 운영시간 밖의 시간은 선택지에 노출하지 않는다.

V2 예약판은 기존 `10:00~22:00` 전용 범위를 제거하고 공통 `07:00~23:00` 범위를 사용한다. 마지막 행은 `22:30`이며 30분 예약만 가능하다.

공개 예약 생성과 시간 변경의 서버 검증도 같은 경계를 검사한다. 화면을 거치지 않은 요청이 운영시간 밖의 예약을 저장하지 못하게 한다. V2 서버 액션도 동일한 정책과 오류 문구를 사용한다.

기존 예약 데이터는 수정하거나 삭제하지 않는다. 관리자 시간표와 점검 시간 등록은 계속 하루 전체 시간을 다룬다.

## 오류 처리

운영시간 밖의 요청은 `예약 가능 시간은 07:00부터 23:00까지입니다.`로 거절한다. 과거 시간, 기존 예약, 점검 시간 충돌 검증은 현재 동작을 유지한다.

## 테스트

- 공통 예약 검증에서 `07:00` 시작과 `23:00` 종료 경계를 허용하는지 확인한다.
- `07:00` 이전 시작과 `23:00` 이후 종료를 거절하는지 확인한다.
- 기본 예약 선택지에서 첫 시작이 `07:00`, 마지막 30분 예약이 `22:30~23:00`인지 확인한다.
- V2 예약판이 `07:00`부터 `22:30`까지 표시되는지 확인한다.
- V2에서 `22:30~23:00`은 허용하고 `22:30~23:30`은 거절하는지 확인한다.
- 기존 충돌, 과거 시간, 점검 시간 테스트와 전체 빌드를 다시 실행한다.

## 제외

- 데이터베이스 제약 조건 추가
- 기존 예약 데이터 변경
- 관리자 시간표와 점검 등록 가능 시간 제한
- 예약 단위와 최대 이용시간 변경
