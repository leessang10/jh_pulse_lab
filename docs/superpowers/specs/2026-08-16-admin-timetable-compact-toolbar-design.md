# 관리자 컴팩트 헤더와 예약 시간표 설계

## 목표

관리자 화면의 중복된 헤더 정보와 과도한 세로 여백을 제거해 주요 콘텐츠가 더 일찍 시작되게 한다. 시간표에서는 빈 시간대를 보고 있어도 현재 선택한 날짜와 날짜 변경 여부를 즉시 알 수 있게 하고, 날짜 필터가 차지하던 공간과 시간표 행 높이를 줄여 같은 화면에서 더 많은 시간대를 확인할 수 있게 한다.

## 확정 범위

- `/admin/reservations`, `/admin/timetables`, `/admin/statistics`의 헤더를 공통 컴팩트 구조로 변경한다.
- 세 화면의 제목과 같은 내용을 반복하는 헤더 배지를 제거한다.
- 통계 헤더의 `기준 월의 예약 이용 현황을 확인하실 수 있습니다.` 설명을 제거한다.
- 공통 헤더는 작은 제목, 모바일 메뉴 버튼과 화면별 우측 액션만 표시한다.
- 페이지 상단 여백, 헤더 높이, 헤더 하단 여백과 첫 콘텐츠 간격을 함께 줄인다.
- 날짜 선택 버튼을 헤더 우측의 `점검 등록` 버튼 바로 왼쪽에 배치한다.
- 모바일에서도 `날짜 선택 → 점검 등록` 순서를 한 줄로 유지한다.
- 기존의 별도 날짜 필터 카드를 제거한다.
- 실제로 다른 날짜를 선택할 때마다 전역 Sonner 토스트를 표시한다.
- 최초 화면 진입과 같은 날짜 재선택에는 토스트를 표시하지 않는다.
- 시간표의 데스크톱 행, 타일, 모바일 카드와 로딩 스켈레톤을 함께 컴팩트하게 만든다.
- 이전/다음 날짜 이동 버튼, 고정 툴바, 데이터 조회 방식 변경은 포함하지 않는다.

## 관리자 공통 컴팩트 헤더

세 관리자 화면이 같은 높이와 반응형 규칙을 유지하도록 `AdminPageHeader` 공통 컴포넌트를 만든다. 이 컴포넌트는 페이지 제목과 선택적인 우측 액션을 입력받고 모바일 사이드바 트리거를 공통으로 렌더링한다. 화면별 조회 상태와 이벤트 처리는 각 페이지에 그대로 두며 액션 JSX만 공통 헤더에 전달한다.

헤더에는 다음 정보만 남긴다.

- 예약 목록: `예약 목록` 제목
- 예약 시간표: `예약 시간표` 제목, 날짜 선택, 점검 등록
- 예약 통계: `예약 통계` 제목, 기준 월, 추세 단위, 정기권 시뮬레이션

중복 배지와 통계 설명은 제거한다. 제목은 `text-2xl`과 촘촘한 줄높이를 사용한다. 페이지 상단 여백은 현재 24px에서 약 16px, 헤더 하단 패딩은 20px에서 약 12px, 헤더와 첫 콘텐츠 간격은 24px에서 약 16px로 축소한다. 데스크톱에서 단순 제목 헤더와 액션이 있는 헤더 모두 약 52~60px 안에서 끝나는 것을 목표로 한다.

예약 통계의 `기준 월`, `추세 단위` 시각 라벨은 제거해 컨트롤을 제목과 같은 한 줄에 놓는다. 각 컨트롤에는 `aria-label` 또는 화면 읽기 전용 라벨을 유지해 의미와 접근성을 보존한다. 기준 월, 단위, 시뮬레이션 순서는 유지한다.

데스크톱에서는 제목과 우측 액션을 한 줄에 배치한다. 좁은 화면에서 액션이 제목 옆에 들어가지 않으면 제목 줄과 액션 줄로만 나누고, 각 줄의 높이와 간격을 최소화한다. 모바일 사이드바 트리거는 제목과 같은 줄에 둔다.

## 헤더와 날짜 선택

시간표 헤더 왼쪽에는 제목과 모바일 사이드바 트리거를 표시한다. 헤더 오른쪽에는 액션 그룹을 만들고 날짜 선택 버튼과 `점검 등록` 버튼을 차례로 배치한다.

날짜 선택 버튼은 현재 날짜 전체 표현을 그대로 노출한다. 버튼을 누르면 기존 달력 Popover가 열리며, 달력의 선택 상태는 현재 시간표 조회 날짜와 동기화한다. 모바일에서는 액션 그룹과 버튼의 간격, 높이와 글자 크기를 줄여 두 버튼이 한 줄에 머물게 한다. 날짜 문자열은 줄바꿈하지 않는다.

별도 `날짜` 카드 전체를 제거하고 시간표 카드를 헤더 다음 콘텐츠로 배치한다. 이를 통해 날짜 선택 상태는 화면 최상단 액션 영역에서 항상 먼저 보이고, 시간표 시작 위치도 위로 당겨진다.

## 날짜 변경 피드백

달력에서 현재 값과 다른 날짜를 선택하면 다음 순서로 처리한다.

1. 선택한 `Date` 값을 한국 날짜 문자열 값으로 변환한다.
2. 현재 날짜와 다른지 비교한다.
3. 날짜 상태를 갱신한다.
4. 전역 Sonner의 일반 정보 토스트로 `<표시 날짜> 시간표로 변경했습니다.`를 표시한다.

토스트의 표시 날짜는 날짜 선택 버튼과 같은 `formatKoreaDate` 결과를 사용한다. 예약 조회 또는 점검 조회의 성공 여부와 관계없이 사용자가 선택한 조회 기준이 바뀌었다는 사실을 알리는 피드백이다. 조회 오류는 기존 화면 내 오류 메시지로 계속 표시한다.

## 컴팩트 시간표

데스크톱 시간표는 한 슬롯의 전체 높이를 현재 약 72px에서 약 48px 수준으로 낮춘다. 다음 요소를 함께 조정한다.

- 시간 열과 연습실 헤더의 세로 패딩
- 행의 최소 높이
- 각 셀의 안쪽 패딩
- 타일의 최소 높이와 세로 패딩
- 타일 본문과 상태 배지의 글자 크기 및 간격

예약자 이름, 예약 시간, 예약 상태, 점검 상태와 빈 시간 표시 정보는 제거하지 않는다. 긴 예약자 이름은 기존처럼 말줄임 처리하며, 상태 배지는 타일 폭을 과도하게 차지하지 않게 축소한다.

모바일 시간표는 시간별 카드 패딩, 카드 간격, 시간 제목 간격과 각 타일 높이를 함께 줄인다. 터치 액션이 있는 예약·점검 타일은 조작 가능성을 유지할 수 있는 높이를 확보하고, 비활성 빈 타일도 같은 높이를 사용해 열을 안정적으로 읽을 수 있게 한다.

로딩 스켈레톤의 높이와 간격도 완성된 시간표 밀도와 맞춰 로딩 전후 레이아웃 변화가 커지지 않게 한다.

## 컴포넌트와 데이터 흐름

기존 각 관리자 페이지의 상태와 조회 훅은 유지한다. 데이터 모델, 예약 취소, 통계 조회, 점검 등록·삭제 흐름은 변경하지 않는다.

- `AdminPageHeader`: 공통 제목, 모바일 메뉴 버튼, 선택적 우측 액션과 반응형 높이를 담당한다.
- 헤더 액션 그룹: 날짜 Popover와 점검 등록 버튼을 렌더링한다.
- 날짜 선택 처리기: 값 변환, 동일 날짜 차단, 상태 변경과 토스트 표시를 담당한다.
- `DesktopTimetable`: 데스크톱 표 밀도만 조정한다.
- `MobileTimetable`: 모바일 카드 밀도만 조정한다.
- `TimetableTile`: 공통 타일의 높이, 패딩, 글자와 배지 밀도를 조정한다.

## 오류 및 경계 조건

- 달력에서 값이 없는 선택 이벤트가 오면 아무 작업도 하지 않는다.
- 현재 날짜를 다시 선택하면 상태 갱신과 토스트를 모두 생략한다.
- 날짜 변경 후 조회가 실패하면 변경 토스트와 별개로 기존 오류 안내를 표시한다.
- 좁은 모바일 폭에서는 날짜 문자열과 점검 등록 버튼을 한 줄에 유지하되, 헤더의 제목 영역과 액션 영역은 서로 다른 줄로 배치할 수 있다.
- 통계 액션은 좁은 화면에서 필요한 만큼 줄바꿈할 수 있지만 화면에 별도 설명 줄을 다시 만들지 않는다.
- 날짜 선택 Popover의 정렬은 액션 그룹 안에서 화면 밖으로 넘치지 않도록 모바일과 데스크톱에 맞춰 유지한다.

## 테스트와 검증

테스트 주도 방식으로 날짜 변경 표시 문자열과 동일 날짜 처리 규칙을 먼저 실패하는 테스트로 작성한다. 최소 구현 후 관련 단위 테스트와 전체 Vitest를 실행한다.

완료 전 다음을 검증한다.

1. 세 관리자 화면에서 배지가 제거되고 제목 크기, 상단 여백, 헤더 높이와 첫 콘텐츠 간격이 일관적인지 확인한다.
2. 통계 헤더의 설명과 시각 라벨이 제거되면서 컨트롤의 접근성 이름은 유지되는지 확인한다.
3. 데스크톱 헤더가 한 줄과 약 52~60px 높이를 유지하는지 확인한다.
4. 날짜 필터 카드가 제거되고 날짜 선택이 점검 등록 왼쪽에 표시되는지 확인한다.
5. 다른 날짜를 선택할 때 한 번만 공통 토스트가 표시되는지 확인한다.
6. 같은 날짜 재선택과 최초 진입에는 토스트가 표시되지 않는지 확인한다.
7. 날짜 변경 후 예약과 점검 데이터가 선택 날짜 기준으로 다시 조회되는지 확인한다.
8. 데스크톱에서 기존보다 많은 30분 슬롯이 한 화면에 보이는지 확인한다.
9. 모바일에서 두 시간표 헤더 액션이 한 줄을 유지하고 예약·점검 타일을 조작할 수 있는지 확인한다.
10. 예약 목록과 통계의 모바일 헤더 액션, 포커스 순서와 화면 넘침을 확인한다.
11. 타입 검사, 전체 테스트, 프로덕션 빌드와 브라우저 콘솔 오류 여부를 확인한다.

## 제외 범위

- 시간표 데이터 또는 Supabase 스키마 변경
- 예약 및 점검 정책 변경
- 이전/다음 날짜 이동 버튼
- 날짜 툴바의 스크롤 고정
- 빈 시간대 자동 접기 또는 숨김
- 헤더와 시간표 이외의 예약 목록·통계 콘텐츠 밀도 변경
