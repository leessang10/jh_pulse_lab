# 점검 시간 표기 가시성 설계

## 목표

메인 원형 시간표에서 점검 시간을 일반 예약과 명확히 구분하고, `00:00-24:00` 점검도 빠짐없이 원 전체에 표시한다.

## 원인

- 점검 세그먼트가 일반 예약 색상 순번을 그대로 사용해 의미가 구분되지 않는다.
- 상세 원형 시간표는 모든 세그먼트에 같은 `opacity`와 흰 테두리를 적용한다.
- 360도 부채꼴은 SVG 시작점과 끝점이 같아 단일 arc 경로가 축약되고 면이 표시되지 않는다.
- 작은 원형 시간표도 예약과 점검을 모두 같은 초록색으로 표시한다.

## 확정 디자인

- 일반 예약은 기존 초록색 계열을 유지한다.
- 점검은 고정된 불투명 앰버색을 사용한다.
  - 면: `#f6d879`
  - 테두리: `#b7791f`
  - 글자: `#5b3a00`
- 점검 면은 `opacity: 1`로 렌더링한다.
- 작은 원형 시간표의 점검 슬롯도 같은 앰버색으로 표시한다.
- 화면 문구를 점검과 예약을 함께 설명하도록 바꾼다.
  - `오늘 예약`에서 `오늘 사용 불가`
  - `예약된 시간`에서 `사용 불가 시간`
- 관리자 시간표와 V2에서 이미 사용하는 앰버 계열 의미를 메인 화면에도 이어간다.

## 구조

- `LandingReservationSegment`에 `kind`, `borderColor`, `foregroundColor`를 추가한다.
- 점검 세그먼트는 고정 점검 토큰을 사용하고 일반 예약만 기존 색상 순번을 사용한다.
- `LandingScheduleSlot`에 점검 여부를 노출해 작은 원형 시간표가 점검 전용 색상을 고를 수 있게 한다.
- 공통 SVG 경로 함수가 360도 구간일 때 두 개의 180도 arc로 완전한 원환을 만든다.

## 테스트

- 360도 원환 경로가 두 개의 외곽 arc와 두 개의 안쪽 arc를 생성하는지 검증한다.
- 점검 세그먼트가 `kind: maintenance`와 점검 전용 색상 토큰을 갖는지 검증한다.
- 점검 슬롯이 작은 원형 시간표에서 점검 전용 클래스를 사용하는지 검증한다.
- 기존 부분 원환 경로와 일반 예약 색상 순번이 유지되는지 검증한다.
- 관련 단위 테스트, 전체 테스트, 프로덕션 빌드, 실제 모바일 화면을 확인한다.

## 제외 범위

- 점검 등록 및 삭제 동작 변경
- Supabase 스키마와 서버 액션 변경
- 관리자 시간표와 V2 레이아웃 변경
- 일반 예약 색상 팔레트 변경
