# 관리자 예약 통계 페이지 설계

## 목표

현재 무료 연습실의 예약 데이터를 이용해 유료 정기권 도입 전 운영 기준을 판단할 수 있는 관리자 통계 페이지를 추가한다.

이 페이지의 우선 목적은 매출을 예측하는 것이 아니라 다음 질문에 답하는 것이다.

- 이용시간과 예약 건수가 일·주·년 단위로 어떻게 변하는가?
- 한 달에 실제로 이용하는 회원은 몇 명이고, 회원당 이용시간은 얼마인가?
- 어떤 회원이 연습실을 많이 이용하는가?
- 요일별로 가장 붐비는 연속 2시간은 언제인가?
- 임의의 정기권 조건을 현재 수요에 적용하면 대상 회원과 단순 매출 시나리오가 어떻게 달라지는가?

## 현재 데이터와 한계

통계는 Supabase의 `reservations` 데이터를 사용한다. 현재 예약 데이터는 2026년 6월 17일부터 있으며, 검토 시점에는 747건과 이름 기준 추정 이용자 35명이 있다.

회원 식별자는 예약자 이름을 정리한 값을 사용한다. 앞뒤 공백을 제거하고 연속 공백을 하나로 합친 뒤 대소문자를 무시한다. 동명이인과 이름 표기 차이 때문에 이용자 수와 회원 순위에는 작은 오차가 있을 수 있다.

취소되지 않은 예약은 실제 이용 수요로 간주한다. 실제 출석이나 노쇼 데이터는 없으므로 출석률은 계산하지 않는다. 데이터베이스의 `pending`과 `confirmed`는 통계 구분에 사용하지 않고, `cancelled`와 그 외 상태만 구분한다. 현재 진행 중인 기준 월은 한국 시간 오늘까지의 예약만 집계하고 이후 예약은 아직 발생하지 않은 이용으로 제외한다.

취소 사유가 없으므로 회원 취소, 관리자 취소, 점검 등록에 따른 자동 취소를 구분하지 않는다. 취소율은 참고 지표로만 사용한다.

## 경로와 관리자 메뉴

- 새 경로: `/admin/statistics`
- 관리자 사이드바에 `예약 통계` 항목을 추가한다.
- 기존 `AdminShell`의 로그인 확인과 반응형 사이드바를 그대로 사용한다.
- 통계 조회는 인증된 관리자 세션에서만 허용한다.

## 화면 구조

화면은 아래 순서로 구성한다.

1. 제목과 상단 조회 컨트롤
2. 핵심 KPI 카드 5개
3. 이용 추세 차트
4. 전체 회원 이용 순위
5. 요일별 피크 시간 차트

모든 설명과 상태 문구는 존댓말로 작성한다.

### 상단 조회 컨트롤

오른쪽에 다음 컨트롤을 한 줄로 배치한다.

1. `기준 월` 선택
2. `일 / 주 / 년` 추세 단위 선택
3. `정기권 시뮬레이션` 버튼

모바일에서는 같은 순서를 유지한 채 여러 줄로 줄바꿈한다.

`기준 월`은 KPI, 회원 순위, 요일별 피크 시간의 공통 기준이다. 미래 월은 선택할 수 없다.

추세 단위는 이용 추세 차트에만 적용한다.

- `일`: 기준 월의 각 날짜를 표시한다.
- `주`: 기준 월을 월요일~일요일 단위로 묶는다. 첫 주와 마지막 주는 월 경계에서 잘라 정확한 날짜 범위를 라벨에 표시한다.
- `년`: 기준 월이 속한 해의 1월부터 기준 월까지 월별로 표시한다.

추세 단위 선택은 페이지 상단에만 둔다. 이용 추세 카드 안에 중복으로 두지 않는다.

### 핵심 KPI

KPI는 모두 선택한 기준 월을 사용한다. 현재 진행 중인 월은 한국 시간 오늘까지를 월간 누계로 사용한다.

1. `총 이용시간`
   - `status <> 'cancelled'`인 예약의 `end_minutes - start_minutes` 합계
2. `총 예약 건수`
   - 예약일(`date`)이 기준 월에 속한 모든 예약 건수
   - 보조 문구에 취소 예약이 포함됨을 표시한다.
3. `전체 이용자`
   - 취소되지 않은 예약자의 정리된 이름 중 고유 개수
   - 보조 문구에 이름 기준 추정임을 표시한다.
4. `이용자당 평균`
   - 총 이용시간 ÷ 전체 이용자
   - 이용자가 0명이면 `0시간`으로 표시한다.
5. `예약 취소율`
   - 취소 예약 건수 ÷ 전체 예약 건수 × 100
   - 전체 예약이 0건이면 `0%`로 표시한다.

각 카드에는 이전 월 대비 증감값을 보조 정보로 표시한다. 현재 진행 중인 월은 이전 월의 같은 날짜까지 비교한다. 첫 데이터가 중간부터 시작해 비교 기간이 완전하지 않으면 증감값 대신 `이전 월 데이터가 충분하지 않습니다.`를 표시한다.

### 이용 추세

shadcn `ChartContainer`와 Recharts 기반 Area Chart를 사용한다. 카드 오른쪽에는 지표 선택만 둔다.

- `이용시간`
- `예약 건수`
- `이용자 수`

초기 선택은 `이용시간`과 `일`이다. 상단 `일 / 주 / 년` 선택에 따라 X축 집계 단위와 라벨을 바꾼다. 빈 기간도 축에서 빠지지 않도록 0값 버킷을 생성한다. 다만 데이터 수집 시작 월의 시작일 이전은 0이 아니라 `데이터 없음`으로 구분한다.

차트 툴팁에는 기간 라벨과 정확한 값을 함께 표시한다. 이용시간은 소수점 한 자리, 예약 건수와 이용자 수는 정수로 표시한다.

### 전체 회원 이용 순위

선택한 기준 월에서 취소되지 않은 예약을 이름 기준으로 묶고 총 이용시간이 많은 순으로 정렬한다.

동률일 때는 예약 건수가 많은 회원, 그다음 이름 오름차순으로 정렬한다. 각 행에는 다음 값을 표시한다.

- 순위
- 회원 이름
- 상대적인 이용시간 막대
- 총 이용시간
- 예약 건수

처음에는 5명만 표시한다. `10명 더 보기`를 누를 때마다 10명씩 추가하고, 마지막에는 남은 회원만 표시한다. 모든 회원이 보이면 버튼을 숨긴다. 기준 월을 변경하면 다시 5명만 표시한다.

현재 규모에서는 해당 월의 전체 집계 순위를 한 번에 받아 클라이언트에서 표시 개수만 늘린다. 회원 수가 크게 증가하면 커서 기반 페이지 조회로 교체한다.

### 요일별 피크 시간

히트맵 대신 shadcn `ChartContainer`와 Recharts 가로 Range Bar를 사용한다. Y축은 월요일부터 일요일, X축은 운영시간 `07:00~23:00`이다.

각 요일에서 예약 점유율이 가장 높은 연속 2시간을 한 개의 막대로 표시한다. 막대 오른쪽에는 `19:00~21:00 · 50%`처럼 시간과 평균 점유율을 숫자로 표시한다.

계산 방식은 다음과 같다.

1. 취소되지 않은 예약을 30분 슬롯으로 나눈다.
2. 요일·시간 슬롯별 점유 수를 해당 월의 동일 요일 수 × 활성 연습실 수로 나누어 점유율을 구한다.
3. 연속된 30분 슬롯 4개의 평균이 가장 높은 2시간 구간을 선택한다.
4. 최고값이 같으면 더 이른 시간대를 선택한다.
5. 해당 요일의 예약이 없으면 막대 대신 `예약 데이터가 없습니다.`를 표시한다.

점검 시간은 예약으로 세지 않는다. 따라서 이 차트는 시설 가용률이 아니라 예약 수요가 몰린 시간대를 보여주는 지표다.

## 정기권 시뮬레이션 모달

상단 버튼을 누르면 shadcn `Dialog`로 연다. 통계 본문에는 시뮬레이터를 상시 노출하지 않는다.

초기 시뮬레이터는 현재 데이터로 설명 가능한 월 시간권 시나리오만 다룬다.

입력값:

- 월 제공 시간
- 월 가격
- 예상 가입률
- 피크 시간 허용 한도

결과값:

- 기준 월에 제공 시간 이상 이용한 잠재 대상 회원 수
- 예상 가입률을 적용한 시나리오 가입자 수
- 시나리오 월매출
- 잠재 대상 회원의 기존 피크 시간 이용 비중

월매출은 `잠재 대상 회원 수 × 예상 가입률 × 월 가격`의 단순 시나리오다. 실제 구매 의향, 지불 의사, 이탈, 미사용 시간은 알 수 없으므로 결과 영역에 `실제 매출 예측이 아닌 가정 결과입니다.`를 항상 표시한다. 입력값과 결과는 저장하지 않는다.

## 데이터 조회와 집계

통계 전용 서버 액션이 기준 월과 추세 단위를 검증한 뒤 Supabase의 인증된 서버 클라이언트로 통계 RPC를 호출한다. 브라우저에서 예약 원본이나 `SUPABASE_SECRET_KEY`를 사용하지 않는다.

Postgres의 단일 `security invoker` 통계 함수가 다음 묶음을 JSON으로 반환한다.

- 데이터 수집 시작일
- KPI와 이전 월 비교값
- 선택한 단위의 추세 버킷
- 전체 회원 순위
- 요일별 피크 시간

함수는 `public`에 생성하되 `PUBLIC`과 `anon`의 실행 권한을 회수하고 `authenticated`에만 실행 권한을 준다. 기존 RLS를 우회하지 않는다. 현재 서비스는 인증 계정을 관리자 전용으로 사용하므로 기존 관리자 읽기 권한과 범위가 같다.

`reservations_lookup_idx`는 이름이 선두 컬럼이라 날짜 범위 통계에 적합하지 않다. 통계 쿼리의 날짜 조건을 위해 `reservations(date)` 인덱스를 별도로 추가한다. 추가 인덱스는 실제 통계 쿼리의 `EXPLAIN (ANALYZE, BUFFERS)` 결과를 확인한 뒤 필요한 경우에만 확장한다.

## 클라이언트 상태와 새로고침

- 기준 월, 추세 단위, 추세 지표를 URL 검색 파라미터에 저장해 새로고침해도 선택을 유지한다.
- 잘못된 파라미터는 현재 월, `일`, `이용시간`으로 복구한다.
- 기준 월이나 단위를 바꾸면 새 통계를 불러오고 차트와 KPI에 Skeleton을 표시한다.
- 회원 순위의 펼침 상태는 기준 월 변경 시 초기화한다.
- 통계 조회 실패 시 기존 값을 지우고 카드 영역에 존댓말 오류 문구와 `다시 시도` 버튼을 표시한다.
- 데이터가 전혀 없으면 오류로 처리하지 않고 모든 KPI를 0으로 표시하며 차트와 순위에 빈 상태를 표시한다.

## shadcn 구성

기존 테마 토큰과 관리자 화면 밀도를 유지한다. 임의 색상 대신 `background`, `card`, `foreground`, `muted`, `primary`, `border` 토큰을 사용한다.

- KPI와 각 영역: `Card`
- 기준 월: `Select`
- 일·주·년 및 추세 지표 선택: `ToggleGroup` 또는 동일한 단일 선택 shadcn 패턴
- 추세와 피크 시간: shadcn Chart
- 정기권 시뮬레이션: `Dialog`
- 로딩: `Skeleton`
- 오류: `Alert`
- 회원 순위 펼침: `Button`

차트는 접근 가능한 툴팁과 텍스트 라벨을 제공한다. 색상만으로 값을 구분하지 않는다.

## 테스트

### 순수 집계 테스트

- 취소된 예약이 이용시간과 이용자 수에서 제외되는지 확인한다.
- 총 예약 건수와 취소율에는 취소 예약이 포함되는지 확인한다.
- 이름의 앞뒤·연속 공백과 대소문자가 정리되는지 확인한다.
- 이용자가 0명일 때 평균이 0인지 확인한다.
- 현재 월의 이전 월 비교가 같은 날짜까지만 계산되는지 확인한다.
- 불완전한 최초 월에는 증감률을 숨기는지 확인한다.
- 일·주·년 버킷과 빈 기간이 올바르게 생성되는지 확인한다.
- 회원 순위의 정렬과 동률 규칙을 확인한다.
- 피크 2시간 계산과 동일 값의 이른 시간 우선 규칙을 확인한다.

### 데이터베이스 테스트

- 비로그인 역할과 `anon`이 통계 함수를 실행할 수 없는지 확인한다.
- 인증된 관리자 역할이 통계 함수를 실행할 수 있는지 확인한다.
- 반환된 KPI 합계가 같은 조건의 직접 집계와 일치하는지 확인한다.
- 날짜 인덱스와 통계 쿼리 계획을 확인한다.

### UI 테스트

- 사이드바에서 예약 통계 경로가 활성화되는지 확인한다.
- 상단에 기준 월, 일·주·년, 정기권 시뮬레이션이 순서대로 표시되는지 확인한다.
- 이용 추세 카드 안에는 일·주·년 선택이 중복되지 않는지 확인한다.
- 기준 월 변경 시 KPI, 순위, 피크 시간이 함께 바뀌는지 확인한다.
- 회원 순위가 5명에서 시작해 10명씩 추가되는지 확인한다.
- 모든 문구가 존댓말인지 확인한다.
- 데스크톱과 모바일에서 차트 라벨과 상단 컨트롤이 겹치지 않는지 확인한다.

## 제외 범위

- 정기권 결제와 실제 판매
- 회원 계정 또는 고유 회원 ID 추가
- 출석·노쇼 기록
- 취소 사유 기록
- 실제 매출·이익 예측
- 통계 데이터 내보내기
- 자동 가격 추천
