# 관리자 점검 시간 설계

## 목표

관리자가 특정 날짜와 연습실을 선택해 30분 단위의 점검 시간을 등록한다. 일반 예약의 30분/1시간 제한과 달리 점검은 `00:00~24:00` 안에서 길이 제한 없이 설정할 수 있다. 점검 시간은 모든 공개 시간표에서 `점검`으로 보이고 일반 사용자가 예약할 수 없다.

## 확정 정책

- 점검은 한 번에 연습실 하나에만 적용한다.
- 시작과 종료는 30분 단위다.
- 종료 시각은 시작 시각보다 늦어야 한다.
- 하루 안에서는 점검 길이에 상한을 두지 않는다.
- 이미 종료된 날짜와 시간대에는 새 점검을 등록하지 않는다.
- 오늘 진행 중인 점검은 시작 시각이 현재보다 앞서도 종료 시각이 현재보다 뒤면 등록할 수 있다.
- 같은 날짜와 연습실의 점검끼리는 겹칠 수 없다.
- 점검과 겹치는 취소되지 않은 일반 예약은 점검 등록과 함께 자동 취소한다.
- 점검을 삭제해도 자동 취소된 일반 예약은 복구하지 않는다.
- 일반 사용자 화면에는 점검 구간을 `점검`으로 표시한다.

## 데이터 구조

Supabase `public` 스키마에 `maintenance_blocks` 테이블을 추가한다.

필드:

- `id uuid primary key`
- `date date not null`
- `room_id text not null`
- `start_minutes integer not null`
- `end_minutes integer not null`
- `created_by uuid not null default auth.uid()`
- `created_at timestamptz not null default now()`

DB 제약 조건으로 활성 연습실 ID, `0~1440` 범위, 시작보다 늦은 종료, 시작·종료의 30분 단위를 검증한다. 날짜·연습실·시간 범위 조회용 인덱스를 둔다.

점검은 일반 예약의 이름, 비밀번호, 상태 의미를 갖지 않으므로 `reservations`와 분리한다. 공개 화면과 관리자 시간표에서는 두 테이블을 일정 블록 뷰 모델로 합친다. 일정 블록은 `reservation`과 `maintenance`를 구분하고, 점검에는 일반 예약 상태나 예약자 정보를 억지로 넣지 않는다.

## 원자적 등록과 충돌 방지

관리자 서버 액션은 Supabase RPC `create_maintenance_block`을 호출한다. 함수는 기본 `SECURITY INVOKER`로 실행하고 `PUBLIC`과 `anon` 실행 권한을 제거한 뒤 `authenticated`에만 실행 권한을 준다.

하나의 DB 트랜잭션에서 다음을 처리한다.

1. 입력값과 관리자 인증을 검증한다.
2. 날짜와 연습실을 기준으로 트랜잭션 잠금을 획득한다.
3. 기존 점검과 겹치는지 검사한다.
4. 점검 행을 생성한다.
5. 같은 날짜·연습실에서 점검과 겹치는 `status <> 'cancelled'` 일반 예약을 `cancelled`로 변경한다.
6. 생성한 점검과 실제 취소 건수를 반환한다.

중간에 실패하면 점검 생성과 예약 취소를 모두 롤백한다.

일반 예약의 INSERT/시간 변경에도 같은 날짜·연습실 잠금과 점검 충돌 검사를 적용한다. 클라이언트의 사전 검사는 사용자 안내용이고, DB 검사를 최종 방어선으로 둔다. 이로써 점검 등록과 일반 예약이 동시에 요청돼도 겹치는 두 데이터가 함께 커밋되지 않게 한다.

## 보안

- 현행 앱은 Supabase `authenticated` 사용자를 관리자 계정으로만 운영한다.
- `maintenance_blocks`에 RLS를 활성화한다.
- `authenticated`에만 SELECT, INSERT, DELETE 정책을 둔다.
- 점검 수정은 지원하지 않는다. 잘못 등록한 점검은 삭제 후 다시 등록한다.
- 공개 클라이언트가 테이블을 직접 읽거나 쓰지 않는다.
- 공개 일정 조회는 기존 서버 액션과 서버 전용 Supabase 클라이언트를 통한다.
- 서비스 키와 관리자 전용 RPC는 브라우저 코드에 노출하지 않는다.

## 관리자 화면

기존 `/admin/timetables` 화면에 `점검 등록` 버튼을 추가한다. 새 사이드바 메뉴나 별도 페이지는 만들지 않는다.

등록창 항목:

- 현재 시간표의 선택 날짜
- 연습실
- 시작 시간
- 종료 시간
- 현재 조회 기준으로 계산한 겹치는 일반 예약 수
- `등록 시 겹치는 예약이 자동 취소됩니다` 경고

등록 성공 시 RPC가 반환한 실제 취소 건수를 토스트로 알리고 시간표를 다시 조회한다. 미리 표시한 취소 예상 건수와 실제 처리 건수가 달라도 실제 반환값을 기준으로 안내한다.

관리자 시간표에서 점검은 일반 예약과 다른 색상으로 `점검 HH:MM~HH:MM`을 표시한다. 점검 타일을 누르면 삭제 확인창을 연다. 삭제 확인창에는 자동 취소된 예약이 복구되지 않는다는 문구를 표시한다. 점검은 일반 예약 목록에는 넣지 않는다.

## 공개 화면과 예약 검증

다음 화면과 흐름에서 일반 예약과 점검을 함께 조회한다.

- 메인 원형 시간표
- `/reservation` 예약 시간 선택
- `/reservations` 예약 시간 변경
- `/v2` 당일 현황판

공개 일정 응답은 일반 예약 블록과 점검 블록을 구분하는 합성 타입을 사용한다. 점검 블록의 표시 이름은 항상 `점검`이다. 예약 가능 시간 계산은 두 종류의 시간 범위를 모두 점유 구간으로 처리한다.

신규 예약과 예약 변경은 화면에서 점검 구간을 선택하지 못하게 하고, 서버 액션에서도 다시 검사한다. DB 충돌 검사가 마지막으로 같은 규칙을 강제한다. 예약 조회와 취소는 기존 `reservations`만 사용하므로 점검이 사용자 예약 내역에 섞이지 않는다.

## 오류 처리

- 시작·종료가 30분 단위가 아니면 등록하지 않는다.
- 범위를 벗어나거나 종료가 시작보다 늦지 않으면 등록하지 않는다.
- 이미 종료된 점검 범위면 등록하지 않는다.
- 기존 점검과 겹치면 새 점검을 등록하지 않고 명확한 오류를 반환한다.
- 인증되지 않은 요청은 등록·삭제하지 않는다.
- 점검 중인 시간에 일반 예약 생성·변경을 요청하면 `점검 시간에는 예약할 수 없습니다.`를 반환한다.
- RPC나 DB 처리 실패 시 일부 예약만 취소된 상태를 남기지 않는다.

## 테스트와 검증

단위 테스트:

- 30분 단위와 하루 범위 검증
- 점검에는 1시간 상한을 적용하지 않는지 검증
- 종료된 범위와 진행 중인 당일 범위 검증
- 일반 예약과 점검을 합친 예약 가능 시간 계산
- 관리자 시간표의 점검 타일 생성
- 공개 화면의 `점검` 표시 데이터 생성

DB 및 액션 테스트:

- 점검 등록과 겹친 일반 예약 자동 취소
- 취소된 예약은 다시 변경하지 않음
- 점검 중복 등록 차단
- 점검 등록 실패 시 전체 롤백
- 점검 삭제 후 기존 예약이 취소 상태로 유지됨
- 점검과 일반 예약의 동시 요청 충돌 차단
- `anon`의 RPC 실행과 테이블 변경 차단

완료 검증:

1. Supabase 최신 변경 사항과 관련 공식 문서를 확인한다.
2. 마이그레이션과 RLS/RPC 권한을 적용한다.
3. 실제 Supabase에서 등록, 자동 취소, 조회, 삭제, 충돌 차단을 확인한다.
4. DB advisor와 마이그레이션 상태를 확인한다.
5. 전체 테스트와 프로덕션 빌드를 통과시킨다.
6. 관리자, 메인, 예약 생성, 예약 변경, V2 화면을 브라우저에서 확인한다.

## 제외 범위

- 여러 연습실 동시 점검
- 반복 점검
- 점검 수정
- 자동 취소된 예약 자동 복구
- 취소 알림 발송
- 점검 사유나 자유 입력 제목
